# CS2 Demo Stats

**Статистика матчей Counter-Strike 2 из GOTV/SourceTV демок**

CLI на Python: читает события демки, восстанавливает игровые раунды и считает
показатели игроков. Бинарный формат обрабатывает [`demoparser2`](https://github.com/LaihoE/demoparser),
а логика статистики, округления раундов и расчёта рейтинга находится в этом проекте.

> Rating 2.0 в отчётах — воспроизводимое приближение, а не официальный рейтинг HLTV.

## Возможности

- Разбор полных демок CS2 `.dem`, `.dem.gz` и `.dem.bz2`.
- Подсчёт K/D/A, ADR, KAST, Impact и приблизительного Rating 2.0.
- CSV с итогами матча и срезом по каждому игроку в каждом раунде; JSON с правилами расчёта.
- Сводка по нескольким картам с объединением игроков по SteamID64.
- Обработка разминки, смены сторон, овертаймов, перезапусков и серверных откатов раунда.
- Защита от случайной перезаписи отчётов и формул в ячейках CSV.

## Установка

Рекомендуется Python **3.12**. Поддерживается Python 3.10–3.14.
Версия парсера демок закреплена: `demoparser2==0.42.2`.

```bash
uv sync
```

Без `uv`:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
```

В Windows используйте `.venv\Scripts\` вместо `.venv/bin/`.

## Одна демка

```bash
uv run cs2stats /path/to/match.dem
```

Сохранить отчёт можно в JSON, CSV и таблицу по раундам:

```bash
uv run cs2stats /path/to/match.dem \
  --json results/stats.json \
  --csv results/players.csv \
  --rounds-csv results/rounds.csv
```

Полезные параметры:

| Параметр | Назначение |
|---|---|
| `--json -` | Вывести JSON в stdout |
| `--include-flash-assists` | Включить флеш-ассисты в APR и компонент ассиста KAST |
| `--trade-window 5` | Задать окно размена в секундах (по умолчанию 5) |
| `--tickrate 64` | Указать частоту тиков для расчёта окна размена |
| `--exclude-round N` | Исключить игровой раунд; параметр можно повторять |
| `--no-post-round` | Не учитывать события после окончания раунда |
| `--force` | Разрешить перезапись существующих отчётов |
| `--quiet` | Не печатать таблицу в консоль |

Например, чтобы отправить JSON в stdout и исключить первый раунд:

```bash
uv run cs2stats /path/to/match.dem --json - --exclude-round 1
```

## Статистика турнира

Команда `cs2tournament` находит демки в указанной папке и строит общие отчёты.

```bash
uv run cs2tournament /path/to/demos --recursive --output results/tournament
```

Игроки объединяются по SteamID64, а не по нику. Если игрок менял ник, алиасы
сохраняются, а для отображения выбирается наиболее частый. Повторные копии одной
демки, включая сжатый и распакованный варианты, учитываются один раз по SHA-256
распакованного содержимого.

В папке результатов создаются:

| Файл | Содержимое |
|---|---|
| `stats.json` | Полная сводка, параметры и состояние обработки |
| `players.csv` | Итоги игроков по всем обработанным картам |
| `player_maps.csv` | Показатели каждого игрока на каждой карте |
| `players.md` | Таблица для чтения |
| `maps/` | Кеш разбора демок |

Общие рейтинги пересчитываются из суммарных событий и числа раундов конкретного
игрока. Рейтинги отдельных карт не усредняются. Если часть файлов не удалось
прочитать, остальные всё равно попадут в отчёт, но он будет помечен как неполный,
а команда вернёт ненулевой код.

## Что означает рейтинг

В проекте используется заданное приближение:

```text
Rating 2.0 ≈ 0.0073 × KAST + 0.3591 × KPR − 0.5329 × DPR
             + 0.2372 × Impact + 0.0032 × ADR + 0.1587

Impact ≈ 2.13 × KPR + 0.42 × APR − 0.41
```

| Метрика | Значение |
|---|---|
| KPR / DPR / APR | Убийства / смерти / учитываемые ассисты на раунд |
| ADR | Фактически снятое здоровье противников на раунд |
| KAST | Процент раундов с убийством, ассистом, выживанием или разменянной смертью |
| Размен | Товарищ убил убийцу в том же раунде в пределах окна размена |

KAST подставляется в формулу как процент от 0 до 100. По умолчанию учитываются
не-флеш-ассисты. Самоубийства, смерти от мира и teamkill входят в DPR; убийство
своего не увеличивает KPR. Урон своим, самоурон и overkill не входят в ADR.

Формулы HLTV и точные правила их компонентов не опубликованы. Поэтому это
приближение не гарантирует совпадения с HLTV до сотых и не является Rating 2.1
или Rating 3.0. Полные параметры и описание методики записаны в JSON.

## Поддержка и ограничения

- Нужны полные GOTV/SourceTV демки. POV-записи могут не содержать состояния всех игроков.
- Поддерживаются `.dem`, `.dem.gz` и `.dem.bz2`; `.zip`, `.rar` и `.zst` сначала распакуйте.
- Разминка и предматчевые раунды исключаются; учитываются смена сторон и овертайм.
- Режимы с возрождениями, боты и вход нового игрока посреди раунда не поддерживаются.
- При неполных или несовместимых данных программа сообщает об ошибке, а не выдаёт нулевую статистику.
- Сами демки и сгенерированные отчёты не нужны для установки и не входят в репозиторий.

## Python API

```python
from cs2demo_parser.models import Options
from cs2demo_parser.parser import analyze_demo

report = analyze_demo("match.dem", Options(trade_window=5.0))
for player in report.players:
    print(player["name"], player["rating_2_0_approx"])
```

## Разработка

Юнит-тесты работают на синтетических событиях и не скачивают демки:

```bash
uv run pytest
uv run ruff check .
```

Интеграционные тесты запускаются только по явно указанным локальным файлам:

```bash
CS2DEMO_TEST_DEMO=/path/to/match.dem uv run pytest -m integration
```

Тесты не загружают демки автоматически. Для дополнительных переменных окружения
и параметров CLI выполните `uv run cs2stats --help` или `uv run cs2tournament --help`.
